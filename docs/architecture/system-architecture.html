② Application Shell, Dependency Wiring & Navigation app/ · MainActivity.kt · navigation/

Manual dependency injection: one AppContainer per process builds every repository and service once; ViewModel factories read it from DeadlineApp. No DI framework.

DeadlineApp

app/DeadlineApp.kt · Application

Owns the lazy AppContainer. In onCreate it starts three non-blocking jobs: anonymous sign-in, network-triggered progress sync and Remote Config refresh. The emulator build type overrides it with EmulatorApplication for tests.

AppContainer

app/AppContainer.kt · composition root
  • Creates data sources and repositories: Progress, Settings, Account/Auth, Leaderboard, Config, plus LevelSource (GeneratedLevelSource).
  • applicationScope (SupervisorJob): work that must outlive the screen that started it (saving a win, settings writes, account switches).
  • SessionGate serialises account changes with sync, transfers and completion recording, so work queued for one user never runs for the next.
  • CompletionRecorder: save win locally → submit to leaderboard with nickname → sync progress.
  • Exposes currentProgress, progressTransfer, gameAudioManager, syncAccountProgress().

MainActivity

MainActivity.kt · single Activity

Edge-to-edge window, wraps everything in DeadlineTheme + Scaffold and hosts AppNavHost. Tells GameAudioManager when the app goes to the foreground / background.

Navigation

navigation/ · Navigation-Compose

AppNavHost wires routes to screens only. Routes: home, level-select, game/{levelId}, result/{levelId}?won&elapsedMillis&previousBestMillis, leaderboard, settings, account, login, register. NavigationActions gives screens plain callbacks and manages back stack (Result replaces Game; Retry / Next Level drop Result).

③ Presentation Layer — Jetpack Compose + MVVM feature/*

Each feature = Screen (stateful wrapper) + stateless Content composable + ViewModel exposing StateFlow<UiState>. Events flow down into ViewModels; immutable UI state flows back up. No game rules live in the UI.

Home

feature/home

HomeViewModel computes Continue: the first unlocked but uncleared level. Play / Continue, Leaderboard, Settings entry points over the campus photo background.

Level Select

feature/levelselect

LevelSelectViewModel lists the 6 levels (2 Semester Weeks each) with lock state and Personal Best from ProgressRepository; shows loading until progress is read so locks are never guessed.

Result

feature/result

ResultViewModel builds win / loss, completion time, Personal Best and "new best" from the route's GameOutcome — never waits for the background save. Next Level / Retry / Level Select.

Leaderboard

feature/leaderboard

LeaderboardViewModel observes the live per-level ranking only while visible; tabs per level, ties share rank (1, 2, 2, 4), own row marked "You", offline shows last cached ranking + Retry.

feature/game — the gameplay screen

GameRoute + GameLoadViewModel

Asks LevelSource for a fresh board off the main thread; GameLoadState = Loading / Ready / Failed (Retry). One new board per visit, kept across rotation.

GameViewModel

Owns one session: forwards GameUiEvent (TileTapped, Undo, Restart) and shake requests to GameEngine, maps GameState → GameUiState. Runs the stress clock only while resumed, owns CompletionTimer, emits audio / haptic events and reports wins to CompletionRecorder. Uses GameBalance from Remote Config.

GameScreen / GameContent

Reads settings first so sensors never start with defaults; attaches GameSensorBinder and AutoLightController to the visible game only. Adapts board size; scrolls when the window is too short.

UI components feature/game/components

GameBoard lays out layered tiles from logical coordinates (bottom layer first) · TileView raised when selectable, dimmed when covered, 48dp touch target · TaskTray 7 slots, warns at one free slot · GameHud timer + StressIndicator (warning band, pulse at Maximum Stress, "Music" slowdown label) · GameActions Undo / Restart · TiltPeekUi Modifier.tiltPeek alpha/offset per layer (render-only).

Sensor seam

GameSensorActions: sensors report intent only (onShake → shuffle request, onTilt → 0..1 peek). GameSensorBinder is the lifecycle-aware bridge; it never mutates GameState.

Settings

feature/settings

SettingsViewModel: music, sound effects, haptics, Shake, Tilt, Auto-light switches save immediately; nickname saved explicitly. Writes on the app scope with retry on failure. TransferProgressSection + TransferProgressViewModel: create / redeem an XXXX-XXXX code to move progress to another phone.

Account

feature/account

AccountViewModel: Profile / Login / Register pages over AccountRepository (email + password, optional). Guests keep playing offline; credentials never persist outside the call.

④ Sensor & Feedback Layer sensor/*

Pure, unit-testable signal processing behind a thin Android adapter. Tuning comes from GameBalance (Remote Config).

Sensor infrastructure

sensor/SensorInfrastructure.kt

SensorGateway / AndroidSensorGateway wrap SensorManager; one Android listener fans samples out to consumers. Lifecycle helper registers in onStart, unregisters in onStop.

Shake-to-Shuffle

sensor/shake

ShakeDetector: gravity removed, exponential smoothing, threshold in g, N consecutive hits, cooldown. ShakeSensorController turns accelerometer samples into one accepted-shake callback. ShakeConfig = tuning.

Tilt-to-Peek

sensor/tilt

TiltSensorController reads pitch from the rotation vector; TiltProcessor maps it to a 0..1 peek with deadzone, smoothing and release hysteresis (TiltConfig). Drives rendering only.

Auto light

sensor/light/AutoLightController.kt

Ambient lux → this Activity's window brightness (0 lux → 15 %, 1000+ lux → 100 %), ignores small changes, restores brightness on exit. Never changes system brightness.

Haptics

sensor/haptic/HapticFeedbackManager.kt

GameHaptic: TILE_SELECT, MATCH, SHUFFLE, SUCCESS, FAILURE, MAX_STRESS. Shuffle haptic fires only when the game accepted the shake.

⑤ Domain Layer — pure Kotlin, no Android APIs domain/*

All gameplay rules, level generation and data contracts. Deterministic and clock-free (time and randomness are injected), so it is fully covered by JVM unit tests.

game/engine + game/model

GameEngine → DefaultGameEngine

Session API: selectTile, undo, shuffle, restart, advanceTime. Selection → tray → triple removal → Coffee/Music effects → win/loss. Multi-step undo (cleared after a committed match). Exposes read-only state.

OverlapGraph

Precomputed "covers" edges between 2×2 footprints on higher layers; a tile is selectable when its blocker count is zero. Incremental update on removal / undo.

CompletionTimer

Monotonic, injectable time source; start / stop / restart owned by the engine session.

Models

GameState (board, tray, status, stress, music slowdown) · Board · Tile · TilePosition (row, column, layer) · TrayState (7 slots) · GameStatus · TileType (11 campus types: Book, Coffee, Laptop, Assignment, Quiz, Reading, Music, Exam, Presentation, Lecture Slide…).

game/stress + game/shuffle

StressManager + StressConfig

Stress grows with active play time (% of maximum per second), never from taps; values clamped to 0..max; High Stress warning threshold.

CoffeeRecovery

A completed Coffee triple removes stress at a Semester-Week-dependent rate.

MusicRecovery

A Music triple removes a little stress and slows accumulation for a period (refreshes, never stacks).

InputDegradation

At Maximum Stress a tap may slip onto a neighbouring selectable tile (seeded random).

BoardShuffler

Redistributes tile types across existing board slots; ids, positions and tray untouched, so overlap data stays valid.

level/generator · level/model · level/solver

LevelSource → GeneratedLevelSource

New random seed per start so replays differ; runs on a background dispatcher.

ValidatedLevelGenerator · LevelGenerator · SeededGenerator

Builds layered boards from LevelConfig, retries until solvable, falls back to a verified FixedLevels board.

SolvabilityValidator + BacktrackingSolver

Bounded DFS using the engine's real overlap and tray rules; a hit limit is "inconclusive", never "unsolvable".

SemesterDifficulty

12 Semester Weeks → 6 levels × 2 weeks; SemesterLevel, WeekConfig, LayoutTemplate scale tile count, types and layers.

progress/

PlayerProgress (completed levels, highest unlocked week, Personal Bests) — every field only improves. CompletionResult / CompletionOutcome, PersonalBest, CompletionRecorder (fire-and-forget), ProgressTransfer + TransferCode (8 chars, 32-letter alphabet, shown XXXX-XXXX).

leaderboard/ · config/ · settings/

LeaderboardEntry, LeaderboardState (Loading / Ranked / Offline / Error), SubmitResult (Submitted / Queued / NotFaster / Failed), LeaderboardFailure. GameBalance = Stress + Shake + Tilt tuning with compiled defaults. PlayerSettings (nickname ≤ 20, audio, haptics, motion, auto-light).

repository/ — contracts

ProgressRepository · SettingsRepository · AuthRepository / AccountRepository (+ AccountValidation) · LeaderboardRepository · ConfigRepository. Interfaces only: the data layer implements them, tests swap in fakes.

⑥ Core (shared) core/*

Cross-cutting building blocks used by every feature.

theme/

DeadlineTheme (Material 3, light + dark, dynamic colour off), brand palette (ink blue, highlighter amber, sticky-note green), Type, Shape, Spacing / Dimens scale (48dp touch targets).

ui/ + ui/components

PrimaryButton / SecondaryButton / TertiaryButton, PhotoBackground (blur + overlay strength), CampusBackgrounds (University of Melbourne photo per level), LoadingContent, ErrorContent, CenteredScrollableColumn.

audio/

GameAudioManager (app-owned; gameplay owns BGM, effects survive navigation, released in background, follows settings) → AudioPlayer / AndroidAudioPlayer (MediaPlayer + SoundPool) with SoundEffectQueue. Events: TILE_CLICK, MATCH, STRESS_MAX.

util/ · dispatcher/

⑦ Data Layer — offline-first repositories, sync & data sources data/*

Local DataStore is the source of truth for gameplay; the cloud is a mirror. Network failures become typed states (Offline, Queued, NotSignedIn) — they can cost a leaderboard placing, never a level. Every Firebase client hides behind a small interface (seam) for JVM tests.

repository/ — implementations of the domain contracts

ProgressRepositoryImpl

Local-first progress: atomic recordCompletion and merge transactions on DataStore.

SettingsRepositoryImpl

Reads / atomically updates PlayerSettings; guarded by SessionGate against account switches.

AuthRepositoryImpl

Anonymous identity by default, one shared sign-in at a time with per-caller timeout; email register (links the guest), login, logout, nickname profile, Guest data migration / recovery.

LeaderboardRepositoryImpl

Live ranking flow; submits only faster times, waits for server ack, otherwise Queued for upload on reconnect.

ConfigRepositoryImpl

Applies previously fetched values, then fetches new ones within a timeout; any failure keeps the current GameBalance.

SessionGate

Mutex-like gate that serialises login/logout with sync, transfers and win recording, scoped to one user id.

sync/ · config/

ProgressSyncManager

Merges local → cloud in one Firestore transaction, then cloud → local; one sync at a time. Runs at startup, after a win, on reconnect. SyncResult: Synced / Offline / NotSignedIn / Refused.

ConflictResolver

Merge without UI: union of completed levels, max unlocked week, faster Personal Best per level. Commutative and idempotent.

NetworkWatcher · ProgressTransferService

Reconnect trigger · create code (sync first, expires within a day, retry on collision) / redeem (merge then sync).

RemoteBalance

Parses and range-checks every Remote Config string into GameBalance; invalid key or inconsistent group → defaults. Never throws.

local/datastore

DeadlineDataStore · AccountDataStore

Single Preferences file (corruption → defaults). Per-account namespaces for progress and nickname; device settings shared; atomic guest → account migration.

ProgressDataSource · SettingsDataSource · GuestMigrationJournal

Type-safe key mapping; malformed values dropped or clamped; durable guest hand-off journal.

remote/firebase

FirebaseAuthDataSource · FirestoreProgressDataSource · FirestoreLeaderboardDataSource · FirestoreProfileDataSource · FirestoreTransferDataSource (server-only reads) · FirebaseRemoteConfigDataSource (1 h min fetch) · ProgressFields schema · NetworkErrors classification.

⑧ On-device Storage

Preferences DataStore file

Player progress (completed levels, unlocked week, Personal Bests as time:achievedAt:levelId), nickname per account namespace, device-wide settings, guest-migration journal.

Firebase local caches

Firestore offline cache + pending-write queue (leaderboard submissions made offline); Remote Config last-activated values; Firebase Auth persisted user.

⑨ Firebase Backend firebase.json · firestore.rules · remoteconfig.template.json

Firebase Authentication

Anonymous accounts for every install (no sign-up needed); optional email + password that links / switches identity. UID keys every cloud document.

Cloud Firestore

  • users/{uid} — profile, nickname
  • progress/{uid} — cloud copy of PlayerProgress, updated by transaction
  • leaderboard/{levelId}/entries/{uid} — one best time per player per level
  • transfers/{code} — progress snapshot, readable by any signed-in user until expiry

Security Rules

Owner-only writes, schema / range validation, leaderboard accepts only faster and plausible times, transfers cannot be listed, changed, deleted or read after expiry.

Remote Config

Live balance tuning without a release: stress rates, recovery, thresholds, shake and tilt parameters (validated client-side, defaults compiled in).

Key Runtime Flows

1 · Startup

  1. DeadlineApp.onCreate builds AppContainer.
  2. Background: anonymous sign-in + profile refresh.
  3. NetworkWatcher → sync progress when online.
  4. Remote Config: apply cached values, fetch new.
  5. MainActivity → AppNavHost → Home. Nothing blocks the first frame.

2 · Play a tile

  1. Tap → GameUiEvent.TileTapped → GameViewModel.
  2. engine.selectTile: InputDegradation (max stress) → tray → triple match → Coffee / Music effects → win / loss.
  3. New GameState → GameUiState StateFlow → Compose recomposes board, tray, HUD.
  4. Audio + haptic events fire; stress clock ticks advanceTime while resumed.

3 · Win & persist

  1. Timer stops; navigate to Result with GameOutcome.
  2. CompletionRecorder (app scope, SessionGate): save locally → unlock next week, Personal Best.
  3. Submit to leaderboard (Submitted, NotFaster, or Queued while offline).
  4. ProgressSyncManager merges with progress/{uid}.

4 · Sensors

Accelerometer→ShakeDetector→onShake→GameViewModel→engine.shuffle()→SHUFFLE haptic
Rotation vector→TiltProcessor→peek 0..1→Modifier.tiltPeek
Light→AutoLightController→window brightness

Each can be switched off in Settings; tapping still covers every essential action.

5 · Accounts & devices

  1. Register: links the anonymous guest to email; guest data migrates atomically.
  2. Login / logout switches the local DataStore namespace under SessionGate.
  3. Transfer code: sync → snapshot to transfers/{code} → other phone redeems → ConflictResolver merge → sync.

Architecture Principles

  • Unidirectional data flow: UI events down, immutable StateFlow UI state up; stateless Content composables are previewable and testable.
  • Pure domain: engine, stress, generator and solver have no Android imports; clock, randomness and dispatchers are injected.
  • Dependency inversion: ViewModels depend on domain repository interfaces; Firebase and DataStore sit behind seams.
  • Offline-first & monotonic progress: local writes first; cloud merges can only improve progress, so conflicts resolve without UI.
  • Sensors as intent: sensors never touch game state directly; the engine applies the same rules as taps.
  • Fail soft: Remote Config, leaderboard and sync failures fall back to defaults or queued states.

Build, Test & CI

  • Gradle Kotlin DSL, single :app module; debug / emulator / release build types (emulator targets the Firebase Emulator).
  • JVM unit tests (app/src/test): engine, stress, shuffle, generator / solver, repositories, sync, ViewModels, sensors' pure processors.
  • Instrumented tests (app/src/androidTest): Compose UI screens, navigation, acceptance flows, Firestore rules & data sources against the Firebase Emulator.
  • GitHub Actions "Android quality": ktlint → testDebugUnitTest → assembleDebug → lintDebug on every PR to main.
